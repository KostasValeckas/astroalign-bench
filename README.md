A software suite for testing alignment methods for astronomical imaging.
This suite contains functionality  to fabricate offset frames (translation, rotation and PSF blurring)
 generated based on a reference (input) FITS file, and then to test the user 
defined allignment methods trying to align the fabricated frames back to the 
reference (input) frame.

**Author**  Kostas Valeckas (for ESO) - kostas.valeckas@nbi.ku.dk

# Quickstart use example 

First, create a virtual environment and install what is in ```requirements.txt```.

The directory ```test_data``` contains three different images: 

```bash
└── test_data
    ├── IMAGE_FOV_prealign_P01_WFI_BB_2018-01-10T02:49:23_0001.fits
    ├── IMAGE_FOV_prealign_P02_WFI_BB_2018-10-17T07:19:24_0001.fits
    └── IMAGE_FOV_prealign_P03_WFI_BB_2018-01-20T01:16:28_0001.fits
```

Run: 

```bash
python prep_files.py --x_offset 1 --y_offset 1 ./test_data 15
```

This will create 15 frames for each of the three input FITS files, with an incremental pixel offset of 1 in both x and y directions (i.e. the last image will have an offset of 14 pixels in both x and y). The output frames will be saved in the same directory as the input files.

It will also create **log files that will guide the tests**. These log files 
are named with this convention:

```bash
./test_data/IMAGE_FOV_prealign_P02_WFI_BB_2018-10-17T07:19:24_0001_log.json
./test_data/IMAGE_FOV_prealign_P03_WFI_BB_2018-01-20T01:16:28_0001_log.json
./test_data/IMAGE_FOV_prealign_P01_WFI_BB_2018-01-10T02:49:23_0001_log.json
```

To run the tests, execute:

```bash
python run_tests.py --all_log_files --delete_files --show_plots --output_dir ./results ./test_data
```

This will execute the tests for all the log files in the directory ```./test_data```, and save the results in the directory ```./results```. The ```--delete_files``` flag will delete the fabricated frames after the tests are completed (this option is meant for larger batch jobs to save space), and the ```--show_plots``` flag will display the plots generated by the tests, before saving them. 

The ```results``` directory:

```bash
├── results
│   ├── IMAGE_FOV_prealign_P01_WFI_BB_2018-01-10T02:49:23_0001_metrics.json
│   ├── IMAGE_FOV_prealign_P01_WFI_BB_2018-01-10T02:49:23_0001_results.pdf
│   ├── IMAGE_FOV_prealign_P02_WFI_BB_2018-10-17T07:19:24_0001_metrics.json
│   ├── IMAGE_FOV_prealign_P02_WFI_BB_2018-10-17T07:19:24_0001_results.pdf
│   ├── IMAGE_FOV_prealign_P03_WFI_BB_2018-01-20T01:16:28_0001_metrics.json
│   └── IMAGE_FOV_prealign_P03_WFI_BB_2018-01-20T01:16:28_0001_results.pdf
```

will contain both metrics for each method tested, as well as plots of the results.

# Frame fabrication options

Currently, the frame fabrication script ```prep_files.py``` supports the following options:

```bash
--x_offset X_OFFSET   (Incremental) offset for x translation (int for whole-pixel, float for sub-pixel)
--y_offset Y_OFFSET   (Incremental) offset for y translation (int for whole-pixel, float for sub-pixel)
--blurr_fwhm BLURR_FWHM
                      FWHM for Gaussian blurring - the blurring is applied after the translation to the pre-aligned frames
--rot_angle ROT_ANGLE
                      Rotation angle in degrees - constant for all fabricated frames, applied after the translation to the pre-aligned frames

```

# Benchmarking logic

The methods are benchmarked by comapring the cartersian distance between the recovered offsets and the true offsets. 
Therefore, any recovered rotation angle needs to be applied to the pre-aligned frames before calculating the translation offsets (see the [section about adding new methods to the test suite](#adding-new-methods-to-the-test-suite)).

# Adding new methods to the test suite

The framework is designed to be easily expandable.

New modules are to be added in the ```methods.py``` module. The new method 
should inherit from the ```AlignmentMethod``` class, and implement a ```run(self)``` method, that populates the ```self.recovered_x_offsets```, ```self.recovered_y_offsets```, ```self.x_error```, and ```self.y_error``` attributes. Any recovered rotation angle needs to be applied to the pre-aligned frame before estimating the offsets - this is also to be implemented in the ```run(self)``` method. For an example, see the implementation of the ```SpacePylot``` class in ```methods.py```.

When this is done, the method should be added in ```run_tests.py```, in the 
beginning of the script:

```python
from methods import AlignmentMethod, MusePipeline, SpacePylot # extend here
...
METHOD_ENUM = {
    "MUSE Pipeline": MusePipeline,
    "SpacePylot": SpacePylot,
    # extend here
    "ALL": [MusePipeline, SpacePylot #, extend here ],
}
```

Once this is done, the test suite will automatically include the new method in the tests, and will generate metrics and plots for it.

# Design 

The framework is designed to be modular in terms of producing data and running the tests. This should allow for wrapping the python procedures into a bash script (or similar) for batch processing of large datasets.
